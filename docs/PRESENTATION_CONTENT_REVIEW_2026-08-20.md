# 2026년 AI 활용 전문가 과정 발표 보완안

## 1. 발표 개요

- **발표일:** 2026년 8월 20일(목)
- **발표 시간:** 발표 7분, 질의응답 3분
- **발표 대상:** AI 활용 전문가 과정 코치·멘토·교육 관계자
- **발표 목표:** 결과 화면보다 현업 문제를 어떻게 정의하고, 검증하고, 피드백을 반영했는지 설명

## 2. 발표 핵심 메시지

> 분산된 투자오더·월별 Excel·사업일정 데이터를 사업 단위로 통합해, 경영진은 한 화면에서 집행현황을 확인하고 실무자는 근거 데이터를 검증·관리할 수 있는 대시보드로 전환했다.

## 4. 문제 정의 보완 원고

### 4-1. 개선 대상 업무

- 투자사업별 승인투자비와 누적투자비를 확인하려면 여러 월별 Excel 파일을 직접 열어야 했습니다.
- 하나의 사업에 여러 투자오더가 연결될 수 있어 오더별 금액을 사업 단위로 다시 합산해야 했습니다.
- 사업 일정은 별도 관리되고, 계획 대비 실적 차이와 지연·단축 사유도 한 화면에서 확인하기 어려웠습니다.
- 경영진용 조회 화면과 실무자용 입력·확정 화면의 목적이 달랐지만 권한과 화면이 명확히 분리되지 않았습니다.

### 4-2. 샘플 기반 구체 사례

- 6월·7월 자료로 동일 투자오더의 월별 실적투자비를 비교했습니다.
- 이후 한 사업에 서로 다른 투자오더가 연결되는 사례를 추가해 검증했습니다.
- 최종 샘플에서는 **4개 사업 × 복수 투자오더 × 6·7월 자료, 총 16개 Excel 파일**을 사업별로 연결해 테스트했습니다.
- 파일의 `C14`를 월별 실적투자비 기준으로 사용하고, `C15:C108` 상세 합계와 일치하는지 별도 검증했습니다.

### 4-3. 문제를 바라본 가설

1. 투자오더 단위가 아니라 **사업 단위**로 데이터를 통합하면 경영진의 조회 시간이 줄어든다.
2. 월별 실적투자비는 파일 전체 임의 합계가 아니라 **업무 규칙으로 정의된 C14**를 기준으로 해야 한다.
3. 집계값 옆에 원본 파일·오더·검증 결과를 남기면 숫자에 대한 신뢰성을 높일 수 있다.
4. 조회자와 입력자의 권한을 분리하면 화면은 단순해지고 운영 책임도 명확해진다.

## 5. 주요 기능 및 구현 내용

### 5-1. 전체 기능 흐름

```text
사번/비밀번호 로그인
        ↓
Supabase Auth + 역할 확인
        ↓
사업관리(기본정보·일정·승인투자비·Rolling Plan)
        ↓
투자비 가져오기(사업 선택 → 복수 Excel 업로드)
        ↓
오더번호 확인 → C14 추출 → C15:C108 정합성 검증
        ↓
사업별·월별 합산 → 누적투자비·집행률 계산
        ↓
대시보드(도넛 차트·바 차트·사업목록·일정·Rolling Plan)
        ↓
안전규정 RAG/AI Agent(공식 문서 근거와 출처 표시)
```

### 5-2. 사용 기술 및 적용 이유

- **Frontend:** React, TypeScript, Vite, React Router
- **데이터 입력:** XLSX 파싱, 투자오더번호 기반 사업 매핑, 복수 파일 합산
- **검증 로직:** `C14` 월별 실적투자비와 `C15:C108` 상세 합계 비교, 음수 환입·조정값 보존
- **Backend/Data:** Supabase Auth, PostgreSQL, RLS, Supabase 기반 동기화
- **시각화:** 소재별 도넛 차트, 사업별 승인·누적투자비 바 차트, 분기·월별 Rolling Plan
- **AI:** 공식 안전문서 기반 RAG, 조회형 Agent Gateway, 투자비 이상·일정 차이 분석 Tool
- **배포:** GitHub, Vercel SPA rewrite, 모바일 반응형 화면
- **MCP:** 자체 LLM·MCP Host·Horizon MCP Server는 설계까지 완료했으며 현재 구현은 보류

### 5-3. 교육 내용과의 연계 작성 가이드

교육 주차 번호는 실제 커리큘럼에 맞춰 아래 `[ ]`를 채워 넣습니다.

- `[ ]주차 문제정의/업무분석:` 투자오더·월별 파일·사업일정의 분산 문제를 사용자 관점에서 재정의
- `[ ]주차 데이터 처리:` Excel 구조 분석, C14 기준 정의, 복수 오더·복수 파일 집계
- `[ ]주차 웹서비스 개발:` React 컴포넌트, 라우팅, 역할별 화면 구성
- `[ ]주차 데이터베이스/권한:` Supabase Auth, RLS, 확정 후 수정 제한
- `[ ]주차 생성형 AI/RAG:` 공식 문서 검색, 인용·출처 보존, 근거 없는 답변 차단
- `[ ]주차 배포/검증:` GitHub·Vercel 배포, 모바일 URL 직접 접근 404 수정, 회귀 테스트

## 6. 시행착오와 학습점

- 처음에는 투자오더별 데이터를 그대로 보여주려 했지만, 실제 업무는 사업 단위 합산이 필요해 데이터 모델을 변경했습니다.
- `C10`이 아니라 `C14`가 월별 실적투자비라는 업무 기준을 다시 확인해 집계 기준을 수정했습니다.
- `C14`와 `C15:C108` 합계 정합성 검증을 추가해 숫자만 보여주는 대시보드의 한계를 보완했습니다.
- 환입·조정으로 음수가 발생할 수 있어 음수값을 오류로 제거하지 않고 원본 의미를 보존했습니다.
- Vercel에서 `/login`, `/dashboard` 직접 접근 시 404가 발생해 SPA rewrite를 추가했습니다.
- 데스크톱에서 보이던 데이터가 모바일에서 보이지 않는 문제를 반응형 레이아웃과 서버 데이터 연동 점검으로 해결했습니다.
- AI Agent는 처음부터 변경 작업을 허용하지 않고, 현재는 조회·분석과 근거 제시에 집중하도록 안전 경계를 설정했습니다.

## 7. 멘토링·코칭 피드백 반영

- **피드백:** 경영진 화면에 입력용 요소가 많고 핵심 투자비가 분산되어 보임
  - **반영:** 사업 기본정보를 1×4 구조로 정리하고 승인투자비·누적투자비·잔여투자비·누적률을 한 영역에 배치
- **피드백:** 사업 일정 표가 중복되고 행·열이 복잡함
  - **반영:** 사업승인·토건착공·기전착공·준공·SOP를 계획/실적 행으로 재구성
- **피드백:** 실적 지연·단축 사유가 hover에서 가려짐
  - **반영:** 사유가 작성된 실적 날짜만 강조하고, 마우스 오버 시 날짜 아래에 사유를 표시
- **피드백:** 투자비 현황의 비교가 직관적이지 않음
  - **반영:** 승인투자비와 누적투자비의 기준·순서·색상을 조정하고 사업별 바 차트로 비교
- **피드백:** 안전규정 확인을 위해 별도 사이트를 찾아야 함
  - **반영:** 공식 문서 범위의 안전규정 RAG 탭과 전 화면 부동 챗봇을 설계·구현

## 8. 결과 및 시연 구성

### 8-1. 권장 시연 순서

1. 로그인: 임원/직책자 조회자와 실무담당자 권한 차이
2. 대시보드: 소재별 도넛 차트에서 사업 목록 확인
3. 사업목록: 승인투자비·누적투자비·집행률·잔여투자비 확인
4. 사업 상세: 계획/실적 일정과 작성된 지연·단축 사유 확인
5. 투자비 가져오기: 사업 선택 → 복수 Excel 업로드 → 검증 결과 확인
6. Rolling Plan: 당해년도 분기 클릭 → 월별 계획/실적 비교
7. 안전 챗봇: 자연어 질문 → 공식 문서 근거·출처가 포함된 답변 확인

### 8-2. 기대 효과

**정량적으로 제시 가능한 현재 근거**

- 4개 사업, 복수 투자오더, 6·7월 자료 총 16개 파일을 사업별로 통합 테스트
- 월별 실적투자비 기준을 `C14`로 통일하고 상세 합계 검증 단계 추가
- 최신 자동화 테스트 126개 통과, 프로덕션 빌드 검증 완료

**운영 적용 후 측정할 지표**

- 월별 투자비 취합·보고에 걸리는 시간
- 사업별 집행률 확인까지의 클릭 수와 담당자 수작업 횟수
- 원본 오류·중복·미매핑 데이터의 검출 건수
- 계획 대비 실적 사유 입력률 및 경영진 조회 빈도

**정성적 효과**

- 경영진은 사업 전체 포트폴리오를 한 화면에서 확인
- 실무자는 일정·투자비·사유를 같은 사업 화면에서 관리
- 숫자의 출처와 검증 결과가 남아 보고 신뢰성 향상
- 안전규정 검색과 질의응답의 접근성 향상

## 9. 인사이트·회고·교육 소감

### 인사이트

- 좋은 대시보드는 데이터를 많이 보여주는 화면이 아니라, 의사결정에 필요한 기준을 먼저 정리한 화면입니다.
- AI를 붙이기 전에 원본 데이터의 업무 규칙과 검증 기준을 확정해야 합니다.
- 조회·입력·확정 권한을 분리하면 기능보다 운영 책임이 먼저 명확해집니다.

### 아쉬운 점과 실패에서 얻은 가치

- 초기에는 샘플 파일의 행 의미를 잘못 해석해 실적투자비 기준을 수정하는 시행착오가 있었습니다.
- 배포 후 모바일 직접 접근과 권한 매핑 문제가 발생했지만, 실제 운영 조건을 조기에 확인하는 계기가 되었습니다.
- 현재는 샘플 데이터 중심이므로 사내 SSO·투자오더 시스템·공식 문서 자동 수집은 후속 과제입니다.

### 교육 소감 초안

한 달 동안 단순히 AI 기능을 붙이는 데서 끝나지 않고, 현업의 데이터 구조와 의사결정 흐름을 다시 정의하는 경험을 했습니다. 특히 Excel 샘플을 직접 검증하면서 업무 규칙을 코드로 옮기는 과정이 가장 기억에 남았습니다. 실패한 해석과 배포 오류도 사용자 관점에서 다시 확인하는 학습이 되었습니다.

## 10. 단기·장기 적용 계획

### 단기

- 사내 SSO와 실제 사용자 권한 체계 연동
- 투자오더 시스템 또는 정기 Excel 산출물 자동 수집
- C14/C15:C108 검증 결과와 원본 파일 이력 저장
- 실제 담당자 파일럿 운영 및 처리시간·오류율 측정
- 안전규정 RAG 문서 승인·갱신 프로세스 정립

### 장기

- 자체 LLM 또는 사내 LLM Gateway 연동
- MCP Host/Client와 Horizon MCP Server 분리 구축
- 투자비·일정·안전문서를 함께 분석하는 업무 Agent 확장
- 다사업장·다법인 포트폴리오 통합
- 누적 데이터 기반 집행 지연 조기경보와 경영진 자동 브리핑

## 11. 발표 마무리 멘트

> 이번 프로젝트의 핵심은 Excel을 차트로 바꾼 것이 아니라, 분산된 업무 데이터를 사업 단위의 검증 가능한 의사결정 정보로 바꾼 것입니다. 다음 단계에서는 실제 사내 시스템과 연결해 샘플 검증을 운영 자동화로 확장하겠습니다.
